## Goldens

Generated by `tests/doc-corpus/generate-goldens.sh` in CI. Tools:

- `pdftotext -layout` — PDF
- `pandoc -t plain` — DOCX, EPUB, HTML
- `xlsx2csv` — XLSX (skipped silently on unsupported files)
- inline python via `<zipfile>` — PPTX (pandoc has no pptx reader)
- `cp` — TXT, MD

## Pass rate

Last CI run on `experiment/doc-readers`: **14/14 = 100%**.

- 13 files pass the ≥0.92 normalized token-set Jaccard bar against their golden.
- 1 file (`pandas.xlsx`) is **exempted** from the similarity bar (see Exemptions
  below) but the reader is still asserted to return non-empty text.

## Exemptions

| File         | Reason                                                                                                                                                                                                                                              |
|--------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| pandas.xlsx  | `xlsx2csv` golden pretty-prints date serials as `01/03/00 12:00`, while OpenXml exposes the raw serial `36528`. `xlsx2csv` also emits a leading comma per row. Implementing both would replicate xlsx2csv's formatting layer, which we don't need. |

The exemption is enforced in `Exemptions.ByFileName` in the test project, not by
lowering the global threshold.

## Known limitations

- **PDF OCR**: scanned PDFs are flagged with `metadata.likely_scanned = true`
  (text length < 100 chars). No OCR runs on Ubuntu CI. macOS Vision OCR
  fallback would be a follow-up and is out of scope for this experiment.
- **DOCX images / equations**: text-only extraction. No images, no MathML.
- **XLSX dates and formulas**: cell values are raw `CellValue.Text`. No date
  formatting, no formula evaluation (we surface the computed value, not the
  formula).
- **PPTX speaker notes**: not extracted, only slide text frames.
- **EPUB nav / metadata** beyond title/author: not surfaced.
- **HTML scripts / styles** are not stripped explicitly — AngleSharp's
  `body.textContent` discards `<script>`/`<style>` content already in practice.
